# Voice Agent 优化与差异化分析

分析日期：2026-10-21。本文是建议方案，不代表新增功能已经实现。

依据：当前本地代码、只读函数探针、当日重新读取的官方任务页和技术文档。
没有修改应用源代码、运行完整测试套件、申请麦克风权限、调用交易工具或发布产品。

## 1. 核心结论

产品主线：**允许用户纠正、取消并核对意图的语音付款安全网关**。

产品定位不再在“通用支付工具”和“语音技术演示”之间切换：

- Voice 是用户交互入口。
- 对话状态和确认绑定是安全决策层。
- Policy Gatekeeper 与 Pharos MCP 是下游工具。
- Payment Preview 是首个可验证场景。
- 事件回放、审计和失败场景是验收方法，而不是主要用户体验。

建议用一句话表达价值：

> Speak. Correct. Verify. — 说清楚，可以改，核对后再行动。

这是待验证的定位，不宣称行业首创，也不声称已证明产品市场匹配。

## 2. 当前基础与真实缺口

| 层级 | 现有基础 | 尚未完成 |
|---|---|---|
| 语音入口 | 固定 JSONL 回放、事件波形、单步查看 | 麦克风、真实 ASR/VAD/TTS、真实音频测量 |
| 轮次管理 | listen/hold/commit_turn/interrupt_tts 规则 | 可靠的语义结束判断、增量片段合并、迟到事件处理 |
| 意图理解 | 关键词候选、受限英文付款解析 | 中英文自然表达、口语数字、多轮纠正、非动作意图识别 |
| 付款安全 | 金额/地址/余额/规则检查、审核到期、草案重检 | 经认证会话中的动作级确认、取消的服务端状态、幂等性 |
| 证据 | 本地审核文件、fixture voice/intent/mandate hash | 本次真实会话与本次草案的端到端关联 |
| 官方集成 | 直接只读 RPC、MCP schema 原型 | 官方 MCP/Skill 的实际可调用组合与调用证据 |
| 交付 | 本地页面、测试、文档 | 有会话隔离的公共演示、评审证据链接与任务对应录屏 |

原型不等于生产钱包；上次记录的 173 项测试通过不等于语音识别或语义准确率达标。

## 3. 本轮已复现的问题

以下探针只执行本地纯函数，不产生付款、RPC 或持久化记录。

| 输入 | 当前结果 | 意义 |
|---|---|---|
| 帮我看看这份合同的付款周期 | 旧分类器给出 send_payment | “提到付款”被当成“要求付款” |
| 查询明天的会议 | 旧分类器给出 check_balance | “查询”没有绑定金融对象 |
| send 0.2 PHRS…；不是，改成0.02 PHRS | 旧提取器仍取 0.2 | 合并轮次后取第一个金额不能处理修正 |
| send 0.02 PHRS 的 partial，接着 400ms silence | commit_turn | 当前实现不保证始终等到默认 700ms；日志理由也会误称跨过阈值 |
| Could you send 0.02 PHRS to …? | 付款解析 invalid | 受限语法不等于自由文本理解 |
| send zero point zero two PHRS to … | 付款解析 invalid | ASR 自然转写结果可能无法进入付款工具 |

代码位置：

- `scripts/duplex_voice_gateway.py:110-178`：规则式轮次判断。
- `scripts/pharos_voice_action_gateway.py:287-347`：合并 committed turns、关键词分类、首个金额。
- `scripts/pharos_voice_action_gateway.py:350-364`：最近三条文本中的确认/取消关键词，不绑定 action revision。
- `scripts/payment_preview.py:100-182`：受限英文语法。

这些是旧处理器/受限解析器的现状，**不是已发生资金损失或网页自动转账的证据**。
网页导入只复制付款文本，旧确认不继承；当前产品没有签名、广播。

## 4. 最值得形成的五项特色

### A. 纠正优先，旧指令立即失效

示例：`0.2 → “不是，改成0.02” → 新意图版本`。

实现：

- 每个待处理动作有 `session_id / action_id / revision`。
- 新用户修正立即使旧审核和确认失效；展示明确字段 diff。
- “暂停/取消”优先于普通解析及工具回调。
- 已发出的只读调用可请求取消，但无论底层是否真正中止，旧 revision 的返回不能恢复流程。
- 不直接“取最后一个数字”：对于多义修正仍追问具体字段。
- ASR final、语义完整、付款审核通过、人类确认是不同事件。

验收：取消或改金额后，迟到的旧转写、旧余额、旧费用和旧确认都无法创建新草案。

边界：只能取消尚未提交的动作；不是撤销已上链交易。

### B. 金融字段理解，而不只是逐字转写

优先覆盖：

- “零点零二”与 `0.02`。
- 中英文混说，原生测试币名称与拼写确认。
- “只问余额”“看看付款条款”与真正动作请求区分。
- 缺金额/代币/收款人时只追问一个关键字段。
- 联系人来自用户明确维护的可信地址簿，不由模型生成地址。
- 同名联系人、同名代币、解析冲突均展示候选并要求选择。

语音表达金额和意图；地址/代币合约事实由可信数据来源提供并视觉核对。
无需强迫用户朗读完整十六进制地址，也不能只靠地址后四位确认。

### C. 有边界的确认，而不是听到“yes”就通过

审核卡包含：网络、代币合约或原生币标记、金额、完整收款人、费用、有效期。
TTS 可播报摘要，但用户必须在可信界面核对。

建议分为：

1. 理解确认：用户要做什么。
2. 当前草案确认：同意当前 action revision 的展示内容。
3. 钱包签名：未来独立步骤，当前范围不实现。

服务端应把确认关联到当前 action、revision、review hash 和到期时间。
修改关键字段或超时后需要重新核对；按动作与版本实现幂等。
当前页面勾选是 UI 门槛，不是经过身份认证的交易授权协议。
语音口令/读回不是说话人认证，不声称防御录音重放、合成语音或旁人说话。

### D. 一张可追溯的“意图收据”

展示：

```text
输入来源（真实麦克风 / 手输 / fixture）
  → 已提交轮次
  → 意图及修正版本
  → 具体 MCP 调用、网络和区块
  → 规则决定
  → 对应版本的人工确认
  → 未签名草案
```

记录模型/解析器版本、候选字段来源、工具结果摘要、policy version、取消原因。
服务端绑定来源；不能相信浏览器自行上报的 `source=microphone`。

当前导入来源主要是 UI 文本，付款 review 请求只发 text/answers/mode；
fixture hash 明确不绑定新付款。两者之间不能直接画“已认证证据链”。

密码学/隐私边界：

- 事件 hash 不是原始语音证明或身份认证。
- 本地可重算 hash 不等于第三方不可篡改证明。
- 当前 EIP-712-shaped 输出不是标准签名摘要；如进入签名阶段再补规范编码、
  明确 domain、nonce、到期验证、签名者及重放防护。
- 不存音频不代表没有隐私风险；转写、地址、备注及其 hash 仍可能泄露信息。
- 默认不持久化原始音频，说明 ASR 处理位置、转写保存期限、导出脱敏和删除策略。

### E. 真实 Pharos 工具组合，而不是品牌皮肤

单次请求内：

```text
语音/文字 → 结构化候选 → 确定性验证
→ Pharos Chain MCP（网络/余额/合约/费用）
→ Policy Skill（依赖这次数据）
→ 人类可读审核 → 新确认 → 未签名草案
```

工具名、结果、调用顺序可查；正式调用而非伪造 trace。
记录“建议调用”与“已调用”分开，失败不伪造成功或回退演示数据。
只给模型本任务需要的只读工具；签名、广播工具不开放。

官方托管 MCP 文档默认主网 1672 / PROS；现有付款测试网为 688689 / PHRS，
旧语音 fixture 为 688688。按显式 network profile、token registry 和运行时
chain ID 校验分离；不能把一个常量全局替换后假定都兼容。

## 5. 工程顺序

### P0：接麦克风前先解决状态与授权边界

1. 给上述误判、金额纠正、提早提交建立回归样例。
2. 引入一个活跃付款动作的显式状态机，先不做并行多付款。
3. 区分 transcript final、committed turn、validated action、confirmed review。
4. 服务端 revision/取消状态/确认关联；异步回包和多标签页不能绕过。
5. 保持旧 CLI fixture 模块隔离，不把旧合并轮次分类直接接到实时输入。

### P1：一条真实语音到审核的最小纵向闭环

1. 点击开始录音、停止、取消；一个 ASR 适配器、明确录音与数据路径。
2. 先使用显式“完成本轮/核对”降低端点误判，再迭代自动 EOU。
3. 一笔付款、少量可信联系人、有限中英表达和数字规格。
4. 一个 TTS 摘要和可立即停止播报的控制；先不宣称全双工。
5. 把当前审核卡及逐项拒绝理由接入同一对话。

### P1：并行整理验收而不是等待完整语音系统

- 已有 Policy Gatekeeper 三类拒绝、审计和公开可复现证明先打包。
- 尽早验证官方 Chain MCP 可用性、网络和最小工具调用。
- 自然语言付款任务补更广自由文本与明确的代币合约校验；
  如采用测试 ERC-20，清楚标注为自建测试代币，不能冒充官方 USDC。
- 每个任务对应独立验收故事和证据，不把同一录像重复包装为不同完成项。

### P2：通过基线后再扩展

- 连续 ASR、自动端点、真实 TTS barge-in、端到端流式取消。
- 更复杂金额/联系人歧义、更多可信代币。
- 可运行 MCP handler/Skill 包、固定版本与能力协商。
- 以测量结果驱动延迟优化；模型和平台选型另行实测。

## 6. 不应被忽略的公共部署工作

当前服务仅回环 Host/Origin，审计目录为单用户本地设计。公共演示不能只换监听地址：

- Session 隔离、鉴权、资源限额和速率限制。
- 审核和记录权限，不暴露所有用户 recent/audit。
- 麦克风同意、HTTPS、凭证只在服务端。
- 上传大小、音频时长、并发、超时、取消及清理。
- 可重复请求的幂等性；服务重启后如何处理待审核动作。
- 公共只读 fixture 演示可独立部署，但不能冒称提供了实时会话。

## 7. UI/叙事优化

建议同一产品分两个模式：

- **使用模式**：主要操作 + 当前对话 + 当前意图/审核卡。
- **开发者/评审模式**：fixture、原始事件、MCP trace、哈希、版本和失败原因。

保留蓝色视觉与字体，不再添加循环装饰：

- 缩短首屏大标题，让用户立即找到可用动作。
- 用户交互正文目标 14–16px，辅助信息 12px 左右；避免当前部分 6–9px 信息承担关键操作解释。
- 金额/地址/修改差异优先于轨道、滚动信息带和币面。
- 用户文案用“正在听 / 等你说完 / 需要补充 / 等待核对 / 已取消”，工程名只在详情。
- Replay / Live / Typed 和主网 / 测试网 / 演示数据分别标注。
- 主按钮在对应能力真的可用后才称“开始说话”，不以假波形冒充录音。

## 8. 最强演示故事（计划，非现成能力）

1. 用户向已配置的演示联系人提出 0.2 枚测试币付款。
2. 系统展示金额候选并提示超限，不能生成草案。
3. 用户说“不是，改成0.02”；卡片显示字段 diff 和旧版本失效。
4. 使用 Chain MCP 读取当前网络/余额/估算费用，Policy Skill 给出决定。
5. 用户在播报过程中说“先别转”；停止播报，待审核动作取消。
6. 展示迟到工具结果没有恢复旧动作，旧确认不能复用。
7. 重新开始审核，用户在卡片中明确核对，生成 unsigned request。
8. 导出脱敏意图收据：来源、修正、调用、规则、确认和草案。

最值得记住的瞬间不是“它转得快”，而是“我改口了，它确实废弃了旧指令”。

## 9. 指标与验收

先建 40–60 条人工核对的小型样例集（建议规模），包括中英混说、数字、噪声、
短暂停顿、修正、取消、延迟回包、模型误提取、工具失败和越界指令。

| 指标 | 说明 |
|---|---|
| 金额/代币/收款人准确率 | 分字段统计，不只统计字错率 |
| 不安全草案率 | 错字段、取消、旧确认、过期版本进入草案的比例 |
| 修正成功率 | 纠正后只更新目标字段，其他已确认字段不漂移 |
| 过早提交率 | 用户尚未说完就进入完整轮次判断的比例 |
| 澄清有效率 | 一次追问补齐必需字段，而不是反复问 |
| 打断延迟 P50/P95 | 分“按钮停止”和“语音检测后停止”，后者待真实语音能力具备 |
| 流程延迟 P50/P95 | 结束发言→转写→意图→MCP→审核，分层记录 |
| 工具证据覆盖率 | 需要链数据的审核有对应实际调用与区块/来源 |

“已知取消/旧 revision 在测试中全部阻断”是发布门槛，不是对未知环境的安全保证。
建议找 5 位目标试用者完成正常、纠正、取消三个场景，验证他们是否理解状态和授权边界。

## 10. 官方验收对应关系

- Policy Gatekeeper：已有功能基础，重点是 Skill 调用包装、三类拒绝证据与可访问演示。
- Natural-Language Payment Agent：需要自由文本/歧义追问、recipient/token-contract/balance validation，
  并展示 unsigned output；不强制语音，不允许自动签名发送。
- Skill + Chain MCP Flow：必须是同一流程中的真实依赖；直接 RPC 或两个分离的演示不等价。
- Voice 是核心交互特色，而不是取得这三项验收资格的替代证据。

## 11. 可选增强：Speaker Guard（2026-10-21 新增建议）

用户提出增加小模型判断说话人。建议纳入真实语音接入之后的实验计划，
用途是**说话人一致性风险提示**，不是资金授权或现实身份认证。
本轮仅加入方案；未采集录音、登记声纹、下载模型或改变应用行为。

### 范围

- 首版只比较“本次声音是否与当前账户主动登记的样本一致”（1:1）。
- 不做任意声音认人、跨用户声纹搜索或多人身份库。
- 说话人分离只回答音频中谁在何时说话，不自动给出可信账户身份。
- ASR 判断内容；speaker embedding 模型提供声音相似性；策略与确认决定是否继续。
  三者不能相互替代。

### 最小流程

1. 在已通过非语音方式验证的会话内，用户明确选择是否登记声音；
   登记、更换、删除均不能只依靠声纹或口头“同意”。
2. 用户主动录制多段样本，进行有效语音时长、噪声、重叠说话检查。
   不从背景录音、公开视频或他人说话中建立模板。
3. 对当前已分段话语提取 embedding，与本账户模板作比较。
4. 输出 `consistent / inconsistent / insufficient_evidence` 三态，
   不把相似度包装成“本人概率99%”。
5. 不一致或证据不足时，不把本轮语音作为新的付款指令；
   清除待确认状态，提示重录或改用可信界面的文字路径。
6. 一致仅表示未触发此风险提示：仍需字段校验、Policy、当前版本的人工核对；
   未来如签名，必须由独立的钱包/认证路径完成。

安全优先级：**任何“停止/取消”都可以先暂停系统和播报**，不必等待声纹通过。
恢复、修改付款或确认需要重新走可信流程，不能因为旁人说“停止”而继续付款。
只读工具的迟到响应也不能恢复已暂停的旧动作。

### 模型验证路线

- 以 SpeechBrain ECAPA-TDNN 预训练 speaker verification 模型作为可复现基线。
  模型卡描述采用 speaker embedding 比较，训练音频为16kHz单声道。
- 中文/混合语音可对比 WeSpeaker 提供的 CN-Celeb 相关模型和配方；
  不能由训练数据名称推断本项目的中文识别质量。
- 先测本机 CPU 的延迟、内存、实际推理依赖和不同设备上的效果，
  再决定是否换小模型、导出或量化。暂不承诺模型大小或移动端实时性。
- 每个模型需单独核对代码/权重许可，阈值用独立验证集校准，不直接沿用模型演示阈值。

### 防重放、AI仿声和认证边界

声纹匹配与 spoof detection 是两个任务。相似声音可能来自录音重放、
TTS仿声或变声；同一用户也可能因麦克风、噪声、感冒、语言变化而得低分。
若评估随机短句挑战，必须绑定本次会话、一次性挑战和到期时间，并检查说出的内容；
它只能作为攻击测试的一部分，不能宣称解决实时仿声或实现了可靠活体认证。

NIST SP 800-63B-4 在其数字身份认证范围内明确不允许 voice biometric comparison。
因此不把本功能宣传为符合该标准的认证因素、MFA、钱包授权、KYC或KYA。
这不是声纹实验的普遍法律禁令，而是不能将它误包装为合规认证能力。

### 隐私与验收

- 声纹向量仍属于敏感生物特征，不因“只保存embedding”就变成匿名数据。
- 优先本地处理；登记前说明用途和留存，模板加密并提供删除/重新登记。
  原始音频默认不持久化；不上传公共服务、不写链上、不进公开审计JSON。
- 审计最多记录所需的风险结果、模型/阈值版本与话语版本，不包含可复用模板。
- 测试应包含同人跨麦克风、短句、噪声、多人重叠、另一位同意参与的测试者、
  录音重放与经授权的合成语音样本。
- 分别报告误接受、误拒绝、拒判覆盖率、攻击场景接受率和端到端延迟；
  EER或干净音频识别率不能单独证明部署安全。
- 必须验证：匹配成功不能跳过付款审核；未知说话人不能改变付款；
  未知说话人的“停止”仍能使系统暂停；重启后不恢复旧确认。

### 产品展示

建议展示“声音与已登记样本一致／不一致／样本不足”，而不是“身份已认证”。
演示亮点：另一位参与者尝试改金额时系统暂停并要求可信界面重新核对；
原用户主动核对后才恢复。公开说明防仿声能力尚在评估。

优先级：P1实验项，依赖真实麦克风输入、明确同意、稳定的话语切分和动作版本管理；
不阻塞 Policy Gatekeeper、官方MCP接入与基础付款任务验收。
